# Scripts

Every script in `scripts/`, with what it does. Run any of them with `--help` for its options. Add a
row when you add or change a script (see `CLAUDE.md`).

| Script | What it does |
|---|---|
| `test_changed.py` | Runs only the tests the changes since a git ref (default `HEAD`, worktree and untracked files included) can break: the changed crate and its dependents, the core modules that mention a changed module, and the slow console and learn tests only when their area changed. `content/` and `Cargo` changes run everything; `--all` is `cargo test --workspace` (run before a commit), `--slow` adds the slow tests, `--dry-run` prints the plan. |
| `sound_table.py` | Writes `crates/f4x-client/content/sound.ron`: the cast sound of each spell (byte 30 of a `SPELLDAT.LBX` record), the music of each global enchantment, and each unit's move and melee sound (set by ReMoM's `NEXTTURN.c`), by the ids of `spells.ron` and `units.ron`. Needs the author's game folder and the ReMoM clone; safe to run again. |
| `item_icons.py` | Writes the original's item picture number (`ITEMDATA.LBX`, byte 30 of a record) as `icon: N` on each row of `crates/f4x-def/content/items.ron`; safe to run again; `--dry-run` reports only. |
| `imaginary_tests.py` | Writes `docs/tests-on-imaginary-units.md`: every test of the workspace that makes up a unit, a battle, a spell's numbers or a rule set (and, apart, one that puts a game object or entity together by hand), by file and line, with the helper it goes through (`spearman()`, `duel()`). A text search, so rows can be false alarms; run it again after fixing tests. `--out` writes another file. |
| `shadow_tests.py` | Writes `docs/tests-on-shadow-settings.md`: every test that reads the shipped content and asserts a number, by crate, file and line, with its first such assert. The worksheet of task 653 (shadow settings: a value of the content typed into a test); a text search, so most rows are scenario inputs. `--out` writes another file. |
| `ron_hashes.py` | Checks the SHA-256 of every `.ron` file of each crate against the crate's `content.sha256` (lists the files changed, added and removed; exit 1 on a difference); `--update` writes the records. The tests `the_ron_files_are_the_recorded_ones` of `f4x-def`, `f4x-lang` and `f4x-client` fail on a difference, so a changed setting is a recorded decision: run `--update` and commit the record with the change. |
| `untested_content.py` | Lists the content ids (spells, units, buildings, abilities, items, ...) that no test of the workspace names, with counts per file; `--names` lists the ids, `--only FILE` narrows it. A start for the test audit (task 302): an id covered only by a loop over the content shows up too. The kinds a test compares row by row with the original (`WALKED` in the script: units, buildings, items, item powers) count as covered. Test code is `tests.rs`, `*_tests.rs`, `tests/` folders and a source file from its `#[cfg(test)]` on. |
| `classify_core_tests.py` | Lists the candidates among the tests in `crates/f4x-core/src` for `tests/it/` (rule "Where a test lives" in `rust_coding_rules.md`): tests that need a `Game` or `Content`, name a shipped id or are over 25 lines, and reach no internals of the crate. One line per file with the counts; `--tests` lists each candidate with its reasons. Heuristic by text, so read a test before moving it. |
| `fetch_wiki.sh` | Saves Master of Magic Wiki pages into `reference/` through Safari and AppleScript (`scripts/fetch_wiki.sh "Melee Attack" Haste`; `--text` also prints the page's text), then strips them with `strip_wiki.py`. Fandom refuses curl and the fetch tools with HTTP 402; a real browser is let in. Needs macOS, Safari and the terminal's permission to control Safari (System Settings > Privacy & Security > Automation). |
| `strip_wiki.py` | Strips the saved Master of Magic wiki pages in `reference/` (`* Master of Magic Wiki _ Fandom.html`) down to the page title, the wiki's menu links and the article with its images, in a small stylesheet of its own; removes scripts, trackers, ads, video players, the site header, right rail and footer, and deletes the files of the page's `_files` folder that the stripped page does not use. Marks a stripped page, so a second run leaves it alone; `--dry-run` shows the savings. Python standard library only. |
| `fork_ai.py` | Freezes the scripted strategic AI (`crates/f4x-ai`) as `crates/f4x-ai-ref`, the reference opponent of `f4x-tools soak-versus`; an existing reference is replaced only with `--replace`; the copy has its own tests off. `--from REF` freezes the AI as of a git ref instead of the working tree. The copy is a standalone package outside the workspace with a `build.rs` that refuses to build while `crates/f4x-ai-ref/STALE` exists; `--mark-stale [REASON]` writes the marker, `--is-stale` tests it, and a fork removes it. |
| `ai_snapshot.py` | `begin [--from REF]` freezes `crates/f4x-ai` (as of REF, default the last commit) into the local `crates/f4x-ai-ref`; `end --keep new\|old` removes the copy, first restoring `crates/f4x-ai/src` from the recorded commit with `old`. |
| `ai_battle.py` | Runs `f4x-tools` with the `reference` feature (`soak-versus`, or `soak` with a reference): never forks `f4x-ai-ref` itself (it stops and asks for `fork_ai.py` by hand when the reference is missing, stale or no longer builds), adds its dependency line to the `f4x-tools` manifest for the build only, so the reference is never repaired by hand. Runs the battle through `cool_run.sh` (paused while the Mac is hot; `AI_BATTLE_NO_COOL=1` opts out) with `--jobs 4` unless given. `soak-versus --mixed-only` plays only the two mixed games of a seed. |
| `archive_done_tasks.py` | Moves finished tasks (summary or title marked "(done)", or struck through) from `docs/TASKS.md` to `docs/TASKS-DONE.md`, keeping the numbers and the done list in ascending order; a row loses the Priority cell of `TASKS.md` on the way. `--dry-run` lists what would move. |
| `cool_run.sh` | Runs a long command (training, soak runs) at low priority and pauses it while the Mac is under thermal pressure; `--state` prints the thermal state. `--boost` is for a long run that may use the whole machine: waits for a cool start, then normal priority, any core, never paused or watched. `--timing` is the relaxed mode for short timing runs: waits for a cool start, normal priority, never paused, warns if the Mac got hot. Builds `thermal_state` when missing. |
| `prune_target.sh` | Cleans `target/debug` and `target/debug-full` (`cargo clean --profile dev` and `debug-full`) when they are over `--max-gb N` (default 10), because Cargo never removes the test binaries and incremental caches of earlier source states (`target/debug` once reached about 600 GB). `--dry-run` only reports; `--install-hook` installs `.git/hooks/pre-push`, which starts it in the background once the push has finished (git has no post-push hook) and never blocks the push. |
| `fix_wrapper_calls.py` | After deleting `Game` wrapper methods, rewrites their callers to go through `game.units()`, `game.economy()` or `game.spells()`, driven by the compiler's "no method named" errors (task 198). |
| `find_wrappers.py` | Lists the functions of the workspace (not `f4x-ai-ref`) whose body is one call: `trivial` (every argument is a parameter), `std` (the call is a standard method) and `task` (something computed around the call), with the caller count; trait-impl methods are skipped. Output is a table for `docs/wrapper-audit.md` (task 654); `--crate`, `--kind`, `--tests`, `--trait-impls`; `--chains` lists wrappers that call wrappers, longest first (task 725; matches by name, so a common name such as `find` or `new` gives false chains); changes nothing. |

Needs the new-revision ROMs (`mt32_ctrl_2_07.rom`, `mt32_pcm.rom`) in `reference/Roland MT-32/rom-new/`. |
| `check_id_aliases.py` | Checks that the alias written beside a number in the Rust code (`BuildingId::new(35) /* city_walls */`, `Ability::new(28), // flying`, `UnitId::new(169) /* demon */`, `units.id_numbered(169) /* demon */`, also `ItemPowerId`, `ItemId` and `Retort`) is the alias of that number in `crates/f4x-def/content/buildings.ron`, `abilities.ron`, `units.ron`, `realms.ron`, `spells.ron`, `races.ron`, `features.ron` or `terrain.ron` (also `RealmId::new`, `SpellId::new`, `RaceId::new`, `spells.id_numbered`, ...). Run it after writing a number by hand; exit 1 lists the wrong ones. |
| `alias_to_number.py` | Rewrites `<registry>.id_of("alias")` and `.by_name("alias")` string literals in the Rust files to the number the alias stands for in `crates/f4x-def/content/*.ron` (`id_numbered(N)`, `by_num(N)`), so code and tests refer to a definition by number (task 467); a call with a variable is only listed. `--dry-run` writes nothing. |
