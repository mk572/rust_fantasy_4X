# Scripts

Every script in `scripts/`, with what it does. Run any of them with `--help` for its options. Add a
row when you add or change a script (see `CLAUDE.md`).

| Script | What it does |
|---|---|
| `test_changed.py` | Runs only the tests the changes since a git ref (default `HEAD`, worktree and untracked files included) can break: the changed crate and its dependents, the core modules that mention a changed module, and the slow console and learn tests only when their area changed. `content/` and `Cargo` changes run everything; `--all` is `cargo test --workspace` (run before a commit), `--slow` adds the slow tests, `--dry-run` prints the plan. |
| `sound_table.py` | Writes `crates/f4x-client/content/sound.ron`: the cast sound of each spell (byte 30 of a `SPELLDAT.LBX` record), the music of each global enchantment, and each unit's move and melee sound (set by ReMoM's `NEXTTURN.c`), by the ids of `spells.ron` and `units.ron`. Needs the author's game folder and the ReMoM clone; safe to run again. |
| `item_icons.py` | Writes the original's item picture number (`ITEMDATA.LBX`, byte 30 of a record) as `icon: N` on each row of `content/items.ron`; safe to run again; `--dry-run` reports only. |
| `untested_content.py` | Lists the content ids (spells, units, buildings, abilities, items, ...) that no test of the workspace names, with counts per file; `--names` lists the ids, `--only FILE` narrows it. A start for the test audit (task 302): an id covered only by a loop over the content shows up too. The kinds a test compares row by row with the original (`WALKED` in the script: units, buildings, items, item powers) count as covered. Test code is `tests.rs`, `*_tests.rs`, `tests/` folders and a source file from its `#[cfg(test)]` on. |
| `classify_core_tests.py` | Lists the candidates among the tests in `crates/f4x-core/src` for `tests/it/` (rule "Where a test lives" in `rust_coding_rules.md`): tests that need a `Game` or `Content`, name a shipped id or are over 25 lines, and reach no internals of the crate. One line per file with the counts; `--tests` lists each candidate with its reasons. Heuristic by text, so read a test before moving it. |
| `export_original_units.py` | Writes `crates/f4x-core/tests/original/units.tsv`, the original's 198 unit rows (melee, ranged, ammo, to hit, defence, resistance, half-moves, cost, upkeep, hits, sight, transport, figures, race, and the movement, attribute and ability flag words) from `UNITTYPE.c` in the ReMoM clone (`~/projects/ReMoM` or `--remom DIR`). Numbers only, so the output is committed; `original_content.rs` compares the content with it. |
| `export_original_races.py` | Writes `crates/f4x-core/tests/original/races.tsv`, the original's 14 race rows (buildings the race cannot build, outpost growth, growth modifier, house type) from `RACETYPE.c` in the ReMoM clone (`~/projects/ReMoM` or `--remom DIR`). Numbers only, so the output is committed; `original_content.rs` compares the content with it. |
| `export_original_spells.py` | Writes `crates/f4x-core/tests/original/spells.tsv`, the original's 214 spell rows (name, casting category, realm, casting and research cost, first parameter) from `SPELLDAT.LBX` of the author's copy of the game. Committed; `original_content.rs` compares the content with it. |
| `export_original_buildings.py` | Writes `crates/f4x-core/tests/original/buildings.tsv` from `BUILDDAT.LBX` (name, cost, upkeep, the two requirements, the replaced building, experience). Needs the author's game folder; the output is committed. |
| `export_original_items.py` | Writes `crates/f4x-core/tests/original/items.tsv` (the 250 prefab items) and `item_powers.tsv` (the powers) from `ITEMDATA.LBX` and `ITEMPOW.LBX`. Needs the author's game folder; the output is committed. |
| `fork_ai.py` | Freezes the scripted strategic AI (`crates/f4x-ai`) as `crates/f4x-ai-ref`, the reference opponent of `f4x-tools soak-versus`, replacing the previous reference; the copy has its own tests off. `--from REF` freezes the AI as of a git ref instead of the working tree. |
| `archive_done_tasks.py` | Moves finished tasks (summary or title marked "(done)", or struck through) from `docs/TASKS.md` to `docs/TASKS-DONE.md`, keeping the numbers and the done list in ascending order; a row loses the Priority cell of `TASKS.md` on the way. `--dry-run` lists what would move. |
| `cool_run.sh` | Runs a long command (training, soak runs) at low priority and pauses it while the Mac is under thermal pressure; `--state` prints the thermal state. Builds `thermal_state` when missing. |
| `fix_wrapper_calls.py` | After deleting `Game` wrapper methods, rewrites their callers to go through `game.units()` or `game.economy()`, driven by the compiler's "no method named" errors (task 198). |
| `import_mom.py` | Imports Master of Magic data from the author's own copy of the game and a ReMoM clone into `content/` (rules data, committed) and `content-local/` (other copyrighted prose, never committed; the help text is no longer written, the game reads only `crates/f4x-client/content/text/en/help/help.ron`); writes an import report (the local files include `event_texts.ron`, the random events' messages from `EVENTMSG.LBX`). It writes only the local files; the game data (`races`, `units`, `buildings`, `spells`, `abilities`, `items`, `realms`, `level_paths`, `rules`) is kept by hand in `content/`. |
| `list_ogbugs.py` | Indexes the `OGBUG` comments in the ReMoM clone (places where the original departs from its manual) into `content-local/`, as a worklist for `docs/help-vs-implementation-conflicts.md`. |
| `install_fonts.py` | Downloads the open-licence fonts listed in `scripts/fonts.json` (pinned sha256, only licences without restrictions) into `reference/fonts/`; `--list`, `--only ID...`, `--pin` fills in new hashes. See `docs/fonts.md`. Standard library only. |
| `button_text_free.py` | Makes the text-free copies of the main screen's buttons (`assets-local/screens/main_screen/button_<name>_00.png` to `crates/f4x-client/assets/button/<name>.png`): the seven menu-bar buttons (style 4 label with its three "shadow down" copies) and the unit window's Done, Patrol, Wait, Build, Meld and Purify (style 0 label, up and locked). The label's ink is found by its colour and its pixels are filled with the marbling of the same row. The client draws the labels itself (`menu_bar_art.rs`, `action_button_art.rs`). Needs Pillow (`.venv`). |
| `button_label_font.py` | Makes `assets/button/label.{fnt,png}`, style 0 with the serif "I" of the original's BUILD picture, the font of the Build button's label. Needs Pillow (`.venv`). |
| `font_match.py` | Ranks the fonts in `reference/fonts` by how closely their pixels match the original's font styles (`assets-local/art/fonts/bmfont`): draws each without anti-aliasing at sizes 5 to 24 (a variable font at its lightest, default and heaviest weight) and scores the overlap of each glyph with the original's. `--style N`, `--top N`, `--sizes MIN MAX`, `--only TEXT`. Needs Pillow (`.venv`). See `docs/fonts.md`. |
| `font_editor.py` | A pixel editor for the BMFont files the client ships (`crates/f4x-client/assets/fonts`): serves `scripts/font_editor.html` on 127.0.0.1:8765, where a glyph is edited on a pixel grid (paint, erase, shift, flip, resize, y offset, advance, undo, live text preview) and saved into the atlas, copied into every colour set; the first save keeps the originals in `assets-local/art/fonts/orig`. `--dir`, `--port`. `f4x-extract art` writes its own copy elsewhere, so it does not overwrite the edits. Needs Pillow (`.venv`). |
| `grey_neutral.py` | Turns the neutral player's colour from brown to grey in the local art: the sixth row of `map/banners.tsv`, the neutral cities, towers and unit backgrounds (only the banner's pixels), and the minimap's neutral colour. Run it after `f4x-extract art` (which writes the original's brown again); running it twice changes nothing. Needs Pillow (`.venv`). |
| `make_banner_colours.py` | Makes the five more player colours (pink, brown, turquoise, dark blue, orange; task 381) in `assets-local/art`: the rows of `map/banners.tsv` and `map/tiles/minimap.tsv` (the neutral colour moves to 10), the cities, towers, node auras and unit backgrounds in each new colour, and the wizards' gems (`wizards/<id>/gem_5` to `gem_9`, `lilwiz` entries 100 and up, listed in `index.tsv`). Run after `f4x-extract art`. Needs Pillow (.venv). |
| `make_banner_flags.py` | Makes the small flags of the banner step into `assets-local/art/banner_flags/`: the five flags of the original's picture (`newgame` 46) cut from the screen's ground at half size (entries 0 to 4), and five more with the hue turned (5 to 9: pink, brown, turquoise, dark blue, orange; `--turn` changes the angles). Needs Pillow (`.venv`) and the extracted art; the output is derived from the original's art, so it stays local. |
| `make_spell_art.py` | Makes the animation of a spell the original has no picture for, from pictures it has: Petrify (Change Terrain's sparkles, `specfx` 8, green to dark brown), into `assets-local/art/spells/<spell>/`. Needs Pillow (`.venv`) and the extracted art; the output is derived from the original's art, so it stays local. |
| `make_app.sh` | Builds the local macOS app `target/Fantasy4X.app` (release build of `f4x-client` plus a copy of `content/`, `crates/f4x-client/content`, `content-local/` and `assets-local/art`, `screens` and `audio`; leaves out what the game never reads: `.xmi` songs, `audio/timbres`, `audio/index.tsv`, `art/manifest.tsv`, `art/fonts` (the fonts are compiled into the client), `.orig` backups, `.DS_Store`, the import report and ogbug index). For this machine only: it carries the local-only art and text. |
| `train_battle.sh` | Trains the battle AI unattended: builds the trainer, runs it through `cool_run.sh` into a fresh `models-local/NAME` folder (never overwrites), picks the best checkpoint by its held-out reward with the advice hidden, writes `STATUS`, `summary.txt` and `best.bpk`. `--detach` runs it in the background (nohup, caffeinate), `--notify` shows a macOS notification at the end, `--dry-run` prints the plan. |
| `tournament.sh` | Runs a neural-against-neural tournament of battle networks unattended (`PLANNED.md` item 25): builds the tools, picks parents from checkpoints by a round robin, makes nudged and noisy variants, plays a Swiss stage and a knockout through `cool_run.sh` into a fresh `models-local/tournament-NAME` folder (`--resume` continues one), and writes the standings, profiles, bracket and the champion's weights. `--detach`, `--notify`, `--dry-run`. |
| `thermal_state.swift` | Prints the macOS thermal pressure level (nominal, fair, serious, critical, or unknown); built to `thermal_state` and used by `cool_run.sh`. |
| `palette_table.py` | Writes the original's 256-colour base palette (`FONTS.LBX` entry 2) as `docs/palette.tsv`: index, 6-bit and 8-bit RGB, hex. Indexes 224 and up are 0 there: the screens and font colour sets fill them at run time. |
| `palette_screens.py` | Writes the colours the original's pictures load into palette indexes 224 to 255 (`docs/palette_screens.tsv`), per file and per distinct colour set (the picture entries that carry it), plus `FONTS.LBX` entries 3 to 8 (whole alternate palettes). Complements `palette_table.py`, whose base palette is black from 224 on. |
| `font_colors_by_screen.py` | Lists every `Set_Font_Colors_15` call in ReMoM's C source (`~/projects/ReMoM`) as `docs/font_colors_by_screen.tsv`: file, function, line, font style, the `Set_Outline_Color` before it, the palette indexes of the 16-entry set and their base-palette colours ("screen" for 224 up, see `palette_screens.tsv`). Reads the colour arrays as the code fills them, straight through. |
| `font_color_sets.py` | Writes the original's 16 built-in font colour sets (`font_colors`, 768 bytes into each `FONTS.LBX` palette entry 2 to 8) as `docs/font_color_sets.tsv`: palette, set, entry, palette index, RGB, hex. Entry 0 of a set is the alias colour; set 15 is the custom one `Set_Font_Colors_15` overwrites. |
| `font_ramps.py` | Writes the colour sets the original's screens make with `Set_Font_Colors_15` (the `RAMPS` list in the script, each with its source screen's palette) as `crates/f4x-client/content/font_colour_ramps.ron` and the constants `crates/f4x-client/src/font_ramp.rs`. Dev-side only; the committed fonts in `crates/f4x-client/assets/fonts` are hand-edited, so do not copy new extractor output over them (see `docs/extract-art.md` section 5). Adding a ramp needs its colour set appended to the finished atlases, not a re-extraction. Whenever a ramp is added: the ramps become colour sets 16+ in the atlases of styles 0 to 5. |
| `palette_swap.py` | Recolours the 14 wizard portraits by region (hair, clothes, backdrop; faces protected), three variants each, into `assets-local/palette-swap/` plus a contact sheet. Needs the extracted art and Pillow (`.venv`, `requirements.txt`). Local-only output. |
| `tools/xmi-play` (own cargo project, not a script) | Console player for the original's XMI songs (task 363 spike): reads an XMI file, uploads the timbres of its `TIMB` chunk from `fat.mt`, renders it on an emulated MT-32 (`mt32-rs`, pinned commit; LGPL, so it lives outside the workspace) to a WAV and plays it with `afplay`. Given a folder it shows a menu of the `.xmi` files (Up/Down, Enter plays, Esc stops the song and returns to the menu, Esc or q in the menu leaves). `cd tools/xmi-play && cargo run --release -- ../../assets-local/audio/music/104_main_menu.xmi`; `-R DIR` renders every song of the folder to `DIR/NAME.ogg` (the files the game plays: `cd tools/xmi-play && cargo run --release -- -R ../../assets-local/audio/music ../../assets-local/audio/music`, about 2 minutes for the 116 songs; needs `oggenc` or `ffmpeg`); `-h` for options. `mt32-rs` is the git submodule `third_party/mt32-rs` (`git submodule update --init`). Needs the new-revision ROMs (`mt32_ctrl_2_07.rom`, `mt32_pcm.rom`) in `reference/Roland MT-32/rom-new/`. |
| `check_id_aliases.py` | Checks that the alias written beside a number in the Rust code (`BuildingId::new(35) /* city_walls */`, `Ability::new(28), // flying`, `UnitId::new(169) /* demon */`, `units.id_numbered(169) /* demon */`, also `ItemPowerId`, `ItemId` and `Retort`) is the alias of that number in `content/buildings.ron`, `abilities.ron`, `units.ron`, `realms.ron`, `spells.ron`, `races.ron`, `features.ron` or `terrain.ron` (also `RealmId::new`, `SpellId::new`, `RaceId::new`, `spells.id_numbered`, ...). Run it after writing a number by hand; exit 1 lists the wrong ones. |
| `alias_to_number.py` | Rewrites `<registry>.id_of("alias")` and `.by_name("alias")` string literals in the Rust files to the number the alias stands for in `content/*.ron` (`id_numbered(N)`, `by_num(N)`), so code and tests refer to a definition by number (task 467); a call with a variable is only listed. `--dry-run` writes nothing. |
